## 已做的核验

35 个缓存目标逐一绑定原始回执，涉及 13 份重新核对哈希的回执文件。历史状态为 34 次失败、1 次建库修复成功；这不是本批的新构建结果。有界引用审查使用已登记的 45,848 个控制对象、213 个案例，并重新核对 26 份匹配的来源文件，不声称覆盖所有潜在消费者。

清理前重新核对全部待删文件与公共 seed 的内容，以及独立只读恢复副本；检查可见进程和容器占用，再逐文件删除并记日志。3 个不同大小文件的实际恢复测试共恢复 760,688,790 bytes，验证哈希、权限和修改时间。全部恢复映射另经[元数据契约检查](restore-contract-check.json)。先前的 [Maven 和 Ant 两例独立建库](../rebuild-check-20261001/README.zh-CN.md)回执重新核验后复用，本批没有重新构建项目。

独立复查确认全部删除路径已不存在、59,307 个保留项仍在，各候选的源码、数据库、seed 和回执路径仍在。见[输入核验](input-check-summary.json)和[清理后复查](post-cleanup-check.json)。路径存在不等于全部数据库重新验证，也不证明完整运行依赖均已备份。

## 恢复

完整逐文件映射、原始回执证据和删除日志另有私有备份；服务器保留独立内容寻址恢复库。使用 [restore_cache.py](../rebuild-check-20261001/restore_cache.py)，配套提供完整清单、`objects/` 和 `evidence/`，先恢复到新的空目录并核对。

GitHub 仅保存脱敏摘要，不含缓存 payload；这些摘要不能单独还原被删字节。必须保留独立恢复库。恢复缓存不等于项目启动或漏洞复现。本批不改写历史案例或其成功状态。
