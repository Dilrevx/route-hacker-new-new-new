## 核验与恢复

9 个目标分别绑定原始回执，涉及 4 份重新核对哈希的回执文件；历史状态为 8 次失败、1 次建库修复成功，不能当作本批的新构建结果。同一案例的不同尝试分开计数。两份来源批次的有界引用检查覆盖同一已登记索引，计数可能重叠，不相加为更大覆盖范围。

清理前重新核对全部待删文件、对应 seed 和独立只读恢复副本，并检查可见进程及容器占用。3 个不同大小文件的实际恢复测试共恢复 760,688,774 bytes，验证内容哈希、权限和修改时间；全部 602,096 条映射通过[恢复契约检查](restore-contract-check.json)。先前的 [Maven 和 Ant 两例独立建库](../rebuild-check-20261001/README.zh-CN.md)回执重新核验后复用，本批没有重新构建项目。

删除后逐项复查：全部待删路径已不存在，28,317 个保留项仍在，各目标的源码、数据库、seed 和回执路径仍在。见[输入核验](input-check-summary.json)和[清理后复查](post-cleanup-check.json)。路径存在不等于完整数据库内容重新验证或全部运行依赖均已备份。

完整逐文件映射、原始回执和删除日志另有私有备份；服务器保留独立内容寻址恢复库。配套使用 [restore_cache.py](../rebuild-check-20261001/restore_cache.py)、完整清单、`objects/` 和 `evidence/`，先恢复到新的空目录并核对。GitHub 仅保存脱敏摘要，不含缓存 payload，不能单独恢复被删字节；独立恢复库必须保留。恢复缓存不等于项目运行或漏洞复现。
