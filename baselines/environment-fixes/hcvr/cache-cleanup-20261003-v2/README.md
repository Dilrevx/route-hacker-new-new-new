## 核验范围

5 个目标逐一绑定 2 份原始回执文件，并重新核对哈希；历史状态均为修复尝试失败。不同尝试独立计数，其中一个案例出现两次，不能算成 5 个不同案例。本批没有新项目构建，也不改变历史状态。

清理前核对所有待删文件及其独立只读副本，检查所有权、可见进程与容器占用；逐文件删除并记日志。实际抽样恢复 3 个不同大小文件，共 760,688,780 bytes，检查内容哈希、权限和修改时间。完整 328,030 条恢复映射通过[契约检查](restore-contract-check.json)。先前的 [Maven 和 Ant 两例独立建库](../rebuild-check-20261001/README.zh-CN.md)回执重新核验后复用，不等于本批重新构建这 4 个案例。

删除后复查确认全部待删路径已不存在，2,248 个保留项仍在，每个目标对应的源码、数据库、seed 和回执路径仍在。见[输入核验](input-check-summary.json)和[清理后复查](post-cleanup-check.json)。有界引用审查基于已登记控制索引，不能证明覆盖所有潜在消费者；路径存在也不等于全部数据库内容重新验证。

## 恢复方式

完整逐文件映射、原始回执和删除日志另有私有备份，独立内容寻址恢复库仍保留。使用 [restore_cache.py](../rebuild-check-20261001/restore_cache.py)，配套提供完整清单、`objects/` 和 `evidence/`，先恢复到新的空目录并核对。

GitHub 的脱敏摘要不含缓存 payload，不能单独恢复被删字节；必须保留独立恢复库。缓存恢复不代表项目启动或漏洞复现。
