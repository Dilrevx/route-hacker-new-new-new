## 怎样核验

候选目录逐一绑定到原始修复回执，重新核对 140 份历史回执的哈希，并在已收集的控制记录范围内检查引用关系。14 份缓存对应 9 次历史失败、5 次历史建库修复成功尝试；这只是历史状态分类，不是本批的新构建结果。相关数据库全部保留。

每个删除文件都重新核对与公共 seed 的内容一致性，并确认独立恢复库中已有哈希匹配的只读副本。应用清理前再次检查全部待删文件、恢复对象及可见进程/容器占用；逐文件删除并记录日志，不递归删除目录。

本批另做了 3 份缓存文件恢复测试，共 760,688,774 bytes，覆盖小文件、中位大小文件及约 761 MB 的大文件，验证内容哈希、权限和修改时间。全部 869,792 条恢复映射另经[元数据契约检查](restore-contract-check.json)。此前的 [Maven 和 Ant 两例独立建库](../rebuild-check-20261001/README.zh-CN.md)回执重新核验后复用，本批没有重新构建这 14 个项目。

清理后另行复查删除文件均已不存在、76,183 个保留项仍在，以及各候选的源码、数据库、公共 seed 和回执路径仍在。见[输入核验摘要](input-check-summary.json)与[清理后复查](post-cleanup-check.json)。路径存在不等于全部数据库内容重新验证，也不证明所有依赖已形成完整备份。

## 恢复依赖什么

完整逐文件映射、原始回执证据和删除日志另有私有备份；服务器保留独立内容寻址恢复库。恢复时使用已有的 [restore_cache.py](../rebuild-check-20261001/restore_cache.py)，将本批完整清单与 `objects/`、`evidence/` 一起提供，先恢复到新的空目录再核对。

GitHub 这里只保存脱敏记录，不含缓存 payload。必须保留独立恢复库；仅有本页、公开 JSON 或修复说明不能还原被删除的字节。缓存恢复也不等于项目启动或漏洞复现。
