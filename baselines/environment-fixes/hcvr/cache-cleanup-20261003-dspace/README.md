# DSpace 重复 Maven 缓存清理第六批

2026 年 10 月 3 日清理 DSpace 7.6.3 的三次历史构建尝试留下的重复缓存，估计净释放 **28.11 GB / 26.18 GiB**。目标位于独立运行工作区，不在 HCVR v10 执行目录内。本批只删除与公共依赖 seed 内容一致、且已有独立恢复副本的普通文件，源码、数据库和修复记录保留。

净释放量是目标文件释放的块数减去本批新增恢复元数据，不重复扣除已有恢复库。目标缓存与恢复库位于不同文件系统，数字是二者合计，不是某一磁盘空闲量差值；临时审计副本和最后回执的小量开销未计入。保留项为 892 个不在 seed 中的文件和 6 个空文件。详见[结构化摘要](summary.json)。

## 核验范围

三个目标分别绑定原始构建回执，历史状态为两次修复失败、一次建库修复成功；它们属于同一个案例，不能计为三个项目。本批没有重新构建项目，也不改变历史结果。

删除前逐一核对文件与独立只读副本，检查所有权、可见进程和容器占用。全部 200,718 条恢复映射通过[契约检查](restore-contract-check.json)，并实际恢复三个不同大小文件，共 760,688,774 bytes，核对内容哈希、权限和修改时间。先前的 [Maven 和 Ant 两例独立建库](../rebuild-check-20261001/README.zh-CN.md)回执重新核验后复用，不等于本批重新构建 DSpace。

删除后核实全部待删路径已不存在，898 个保留项仍在，源码、数据库、seed 和回执路径仍在；精确版本源码归档和原始回执再次通过哈希检查。见[输入核验](input-check-summary.json)和[清理后复查](post-cleanup-check.json)。引用审查覆盖既有控制索引及新增 529 份控制文件，是有界检查，不能证明覆盖所有潜在消费者；数据库路径存在也不代表其全部内容重新验证。

## 恢复方式

完整逐文件映射、回执、引用审查和删除日志另有私有备份，独立内容寻址恢复库保留。使用 [restore_cache.py](../rebuild-check-20261001/restore_cache.py)，配套提供完整清单、`objects/` 和 `evidence/`，先恢复到新的空目录并核对。

GitHub 的脱敏摘要不含缓存 payload，不能单独恢复被删字节；必须保留独立恢复库。缓存恢复不代表应用启动或漏洞复现。
