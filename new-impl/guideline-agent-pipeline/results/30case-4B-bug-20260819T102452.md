# 30-case Qwen3-Embedding-4B stage-2 defect report

## Status

This report documents a real 30-case stage-2 feasibility run and the harness
defects that made its reported 1/30 method-level result unsuitable for a paper
ablation table. It is not a 143-case result and it does not evaluate PoC
confirmation.

The frozen Unified V2 paper-eval receipt contains 143 cases: 45 IRIS-derived,
68 non-IRIS no-fixed-source/sink proxy, and 30 non-IRIS source-sink/contrast/
other. The pilot consumed 30 completed rows from the Qwen3-Embedding-4B recall
receipt. The stage-2 model was DeepSeek-V4-Pro through local TraeX.

## Correct experiment semantics

The guideline is intentionally a type-level security obligation, not an
original-CVE description. It should constrain the auditor to a narrow class of
risk. For example, a guideline about SQL LIKE-pattern misuse should cause the
auditor to investigate that misuse rather than switch to generic SQL injection.
It must not reveal a CVE identifier, vulnerable method, patch, advisory, or
case-specific root cause.

The prior harness violated this intent in two opposite ways. It used an overly
small readable context while build_guideline could append a case description.
The resulting result was neither a faithful generic-guideline audit nor a fair
test of the recall output.

## Defects in the old stage-2 protocol

1. The prompt listed 20 candidates but, when inline context was enabled, gave
   the model only the first 8 excerpts, with 20 surrounding lines each, and
   prohibited repository reading, search, and tool use. The remaining anchors
   were only metadata. In the 30 recall receipts, known-truth overlap was 2/30
   in the readable Top-8, 3/30 in Top-20, 5/30 in Top-100, and 9/30 in Top-200.
2. The prompt required at most one primary finding, normalization truncated
   output to one finding, and scoring again selected one finding. This made one
   early candidate choice decide the entire case result.
3. build_guideline appended a case description in some cases. This can include
   original vulnerability details and violates the requirement that guideline
   input remain type-level rather than CVE-specific.
4. Stage-2 was therefore not consuming a realistic Top-K candidate set. In a
   deployment setting the evaluator cannot know which recalled candidate is the
   hit, so it must audit all selected Top-K candidates rather than an oracle
   subset or a silent Top-8 prefix.

## Implemented repair on this branch

The ablation harness now uses one agentic, read-only harness session per case.
It passes all selected Top-K candidates in labelled prompt batches; batches only
organize a large prompt and never spawn one session per anchor or truncate Top-K.
The default Top-K is 200 and the default prompt batch size is 30. The agent is
allowed to explore the local checkout read-only from candidate anchors, including
callers, callees, guards, state transitions, data flow, and sensitive effects.
Optional inline excerpts are supplementary only and no longer form a reading
boundary.

The prompt requires the agent to stay in the supplied guideline family and to
emit every distinct concrete in-scope finding it can localize. The parser keeps
all valid findings. Scoring preserves the paper case-level recall definition:
a case is TP if any emitted finding overlaps a frozen trace method; a case is FN
if none does. Every emitted non-overlapping finding counts as FP, and Alarms is
the raw emitted-finding total.

For the normal stage-2 path, the new type-guideline projection retains only
HCVR type, generic guideline text, and CWE class. It excludes the case
description and leaves CVE/case identity out of the prompt unless an explicit
bookkeeping option is requested.

## Verification

The new unit coverage checks that all 65 provided candidates survive into three
prompt batches, the prompt permits agentic exploration and multiple findings,
the CVE identifier is absent by default, normalization preserves multiple
findings, and scoring keeps case-level recall while counting raw multi-finding
alarms and per-finding false positives. Python compilation and direct test
execution passed. The system Python currently has no pytest module, so the test
functions were executed directly with temporary directories.
